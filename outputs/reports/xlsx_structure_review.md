# 원본 XLSX 구조 점검 (초안)

- **대상 파일**: `data/raw/ganaswim_dataset.xlsx` (2,159,941 bytes)
- **점검 방식**: **읽기 전용**. 원본을 열기만 했고 저장·수정하지 않음
- **점검 도구**: pandas 3.0.5 / openpyxl 3.1.5 (`read_only=True`)
- **상태**: 초안. 아래 "추가 확인 질문"에 답이 나오기 전까지 가공 단계로 넘어가지 않음

> 이 문서는 **발견한 사실**만 적는다. 값 수정·열 이름 표준화·CSV 변환은 수행하지 않았다.

## 1. 시트 분류

전체 **19개 시트**. 성격이 다르므로 세 종류로 구분한다.

| 구분 | 시트 | 성격 |
|---|---|---|
| **문서 시트** (분석 대상 아님) | `README`, `data_dictionary` | 데이터 자체가 아니라 데이터에 대한 설명. 집계에 넣지 않는다 |
| **마스터 시트** (기준 정보) | `category_master`, `product_master`, `sku_master`, `channel_master`, `warehouse_master`, `promotion`, `inventory_policy` | 변하지 않는 기준값. 행이 적고 PK가 명확 |
| **거래·이벤트 시트** (분석 본체) | `orders`, `order_item`, `order_attribution`, `returns`, `promotion_application`, `purchase_order`, `receipt`, `inventory_snapshot`, `traffic_daily`, `action_log` | 실제 발생한 사건 기록. 행이 많고 날짜를 가짐 |

### 문서 시트 내용 요약

**`README` (9행 × 4열)** — 헤더 없는 자유 서식(키-값 나열)이라 표 데이터가 아니다. 담고 있는 내용:

| 항목 | 내용 |
|---|---|
| 데이터 기간 | 2026-02-01 ~ 2026-07-31 |
| 분석 기준일 | **2026-07-31** |
| 통화 | KRW |
| 데이터 성격 | 실제 거래가 아닌 **교육용 합성 데이터** |
| 품질 주의 | "정상적인 공란과 입력·연계 오류가 함께 존재" — 사전 점검 필요를 명시 |
| 매출 정의 | 판매단가×(수량−canceled_qty) − 쿠폰할인액 유효수량 배부 − 완료 반품 환불 |
| 비용 정의 | 원가·채널수수료·결제수수료·풀필먼트·포장·반품처리비 반영 공헌이익 |
| 재고주수 정의 | 기준일 가용재고 ÷ (최근 28일 순판매수량 ÷ 4) |
| 액션 기준 | `inventory_policy`의 `clearance_point_wos` + 품절 위험 병행 |
| 주의 | "정책 테이블은 교육용 승인 기준이며 정답이 아님" |

**`data_dictionary` (165행 × 6열)** — 컬럼 사전. 다음 사실을 확인했다.
- 커버 범위: **17개 테이블 전부** (`README`, `data_dictionary` 자신 제외). 누락 테이블 없음
- 그러나 `description` 값이 **단 2종**("행 식별 또는 기준 필드" / "운영 원천 필드")뿐이라 **컬럼별 실제 의미 설명이 아니다.** 사전으로서의 정보량이 낮음
- `key_type`은 165개 중 41개만 채워져 있고(`PK/기준`, `FK 후보`) 124개는 공란
- → **컬럼 의미를 이 사전에 의존할 수 없다.** 의미는 별도로 확인이 필요하다 (질문 Q1)

## 6. 추가 확인 질문

가공 단계로 넘어가기 전에 답이 필요한 항목이다. 번호 순서는 중요도 순.

**Q1. 컬럼 의미의 근거를 어디에 둘 것인가?**
`data_dictionary`의 `description`이 2종류 문구뿐이라 컬럼별 실제 의미를 담고 있지 않다. 예를 들어 `order_item.배송비배부액`이 고객 부담인지 회사 원가인지, `채널수수료액`이 이미 차감된 금액인지 알 수 없다. 별도 정의서가 있는지, 없다면 README의 비용 정의를 유일한 근거로 삼을지.

**Q2. 분석 기준일을 2026-07-31로 고정하는가?**
README는 2026-07-31을 기준일로 명시한다. 이를 프로젝트 상수로 고정할지 확인이 필요하다. 고정하지 않으면 실행 시점마다 재고주수·최근 28일 판매가 달라져 결과 재현이 불가능하다.

**Q3. 기준일 이후 날짜(9건)를 어떻게 처리하는가?**
`cancel_date` 2건(~08-02), `returns.처리일` 7건(~08-06)이 기준일 이후다. ① 기준일 이후 이벤트는 미발생으로 간주(=미완료 취급) ② 데이터에 있는 대로 반영, 두 방식이 매출·반품 금액을 다르게 만든다.

**Q4. 주문상세가 없는 `구매확정` 주문 3건은 오류인가?**
`O0002258`, `O0002648`, `O0004755`. 주문 수 기준 지표와 매출 기준 지표가 어긋나는 원인이 된다. 원천 누락인지, 분석에서 제외할지.

**Q5. 재고 항등식의 기준은 무엇인가?**
`on_hand = available + reserved + damaged`가 12,369행 중 12,366행에서 성립한다. 이 식을 공식 기준으로 삼을지, 그리고 성립하지 않는 3행(`S00363`/03-29, `S00178`/04-30, `S00145`/05-24)을 어떻게 처리할지.

**Q6. 재고주수 계산 시 `available_qty`만 쓰는가?**
README의 재고주수 정의는 "가용재고"라고만 되어 있다. `in_transit_qty`(현재 전 행 0)와 `damaged_qty`를 포함할지 여부를 명시해야 한다.

**Q7. 6~7월 발주 0건은 사실인가?**
발주 데이터가 5월 31일에서 끊긴다. ① 실제로 시즌 중간 발주를 중단한 상태 ② 데이터 추출 범위가 5월까지 — 어느 쪽인가에 따라 "리오더 판단"의 전제가 완전히 달라진다.

**Q8. 입고수량이 발주수량보다 정확히 1 적은 27건의 의미는?**
전부 −1이라 부분 입고라기보다 규칙적 차이로 보인다. 검수불량(합계 46개)과 별개 항목이다.

**Q9. `promotion.적용채널`의 파싱 규칙은?**
`CH01`, `CH01|CH02`, `전체` 세 형태가 섞여 있다. `전체`는 운영 중인 5개 채널 전부를 뜻하는 것으로 보이나 확인이 필요하다.

**Q10. `orders.customer_id` 결측 1,008건(14.3%)은 비회원인가?**
신규 고객·재구매 분석의 모수가 달라진다. `traffic_daily.new_customers`와의 관계도 함께 확인이 필요하다.

**Q11. attribution 모델 2종을 어떻게 다루는가?**
`last_touch` 6,340행 / `linear_assist` 1,130행이 한 테이블에 섞여 있다. 주문별 가중치 합계는 1이지만, 채널 성과를 볼 때 모델을 분리할지 합칠지 결정이 필요하다.

**Q12. 매출·이익의 집계 단위(grain)를 무엇으로 고정하는가?**
`orders`(7,044행)와 `order_item`(8,831행)의 행 수가 달라, 어느 쪽을 기준으로 세느냐에 따라 숫자가 달라진다. 금액은 `order_item`, 주문 수는 `orders`로 고정할지 확인이 필요하다.

## 7. 이번 점검에서 하지 않은 것 (통제 준수)

지시에 따라 아래는 **수행하지 않았다.**

- ❌ CSV·parquet 변환 — 원본만 읽었고 어떤 파일도 생성하지 않음
- ❌ 값 수정·결측 보정 — 결측 20건짜리 `주문시_상품명` 복원도 하지 않음
- ❌ 열 이름 표준화·타입 캐스팅 — 날짜 문자열도 그대로 둠
- ❌ 이상값 제거·행 필터링
- ❌ 지표 계산 (매출·공헌이익·재고주수 등)

원본 파일 `data/raw/ganaswim_dataset.xlsx`는 열기 전용으로 접근했으며 수정 시각·크기 변동 없음.
